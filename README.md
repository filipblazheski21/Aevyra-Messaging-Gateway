# Aevyra Messaging Gateway

Внатрешна апликација на тимот на Aevyra за одделно управување со пациентски информативни контакти по клиника и со маркетинг контакти на Aevyra. Системот има веб-апликација, PostgreSQL база и одделен worker процес. Вистинското испраќање не е имплементирано и `REAL_SENDING_ENABLED` мора да остане `false`.

Започнете со [предавањето](HANDOFF.md). Самостојните деловни барања се во [PROJECT_BRIEF](docs/PROJECT_BRIEF.md), архитектонските детали во [ARCHITECTURE](ARCHITECTURE.md), реалните проверки во [TESTING](TESTING.md), а следните фази во [ROADMAP](ROADMAP.md).

## Преземање

```powershell
git clone <URL-на-приватниот-репозиториум>
Set-Location Aevyra-Messaging-Gateway
npm.cmd ci
```

Не користете ZIP од непроверен извор и не копирајте туѓи `.env` датотеки. Секој развивач создава сопствени локални тајни.

## Предуслови

- Node.js 24 LTS и npm 11. Проверената комбинација е Node.js 24.19.0 и npm 11.17.0.
- При првата инсталација е потребен пристап до јавниот npm регистар и официјалниот SheetJS CDN.
- Docker со активен Linux engine и Docker Compose со поддршка за `up --wait`, за локалната база. Compose користи `postgres:18.6-bookworm`.
- Windows PowerShell. Командите подолу се извршуваат од коренот на проектот. `npm.cmd` работи и кога правилата на PowerShell не дозволуваат `npm.ps1`.

## Локална конфигурација

```powershell
npm.cmd ci
if (-not (Test-Path -LiteralPath .env.admin)) { Copy-Item -LiteralPath .env.admin.example -Destination .env.admin }
```

За нов волумен, поставете локална административна лозинка во `POSTGRES_PASSWORD` и усогласете ја `DATABASE_ADMIN_URL` со истата сметка, база и порта во `.env.admin`. Кодирајте ги знаците со посебно значење во URL. За постоечки волумен, зачувајте ги иницијализираните административни вредности. Compose ги користи `POSTGRES_*` за иницијализација на празен волумен.

За нова апликациска конфигурација, создајте `.env` со независни случајни вредности од 32 бајти за лозинката на PostgreSQL улогата и `AUTH_SECRET`. Командата ја одбива постоечката `.env`.

```powershell
node --env-file=.env.admin --input-type=module -e 'import { randomBytes } from "node:crypto"; import { writeFileSync } from "node:fs"; const u = new URL(process.env.DATABASE_ADMIN_URL); u.username = "aevyra_app"; u.password = randomBytes(32).toString("base64url"); writeFileSync(".env", ["DATABASE_URL=" + u.href, "REAL_SENDING_ENABLED=false", "TZ=Europe/Skopje", "AUTH_SECRET=" + randomBytes(32).toString("base64url"), "AUTH_BASE_URL=http://127.0.0.1:3000", "AUTH_LOCAL_HTTP=true", ""].join("\n"), { flag: "wx", mode: 0o600 })'
```

За постоечка `.env` од Чекор 2Б, следнава команда ги додава само недостасувачките auth поставки со локални стандардни вредности.

```powershell
node --input-type=module -e 'import { randomBytes } from "node:crypto"; import { readFileSync, appendFileSync } from "node:fs"; import { parseEnv } from "node:util"; const env = parseEnv(readFileSync(".env", "utf8")); const auth = { AUTH_SECRET: randomBytes(32).toString("base64url"), AUTH_BASE_URL: "http://127.0.0.1:3000", AUTH_LOCAL_HTTP: "true" }; const lines = Object.entries(auth).filter(([key]) => !Object.hasOwn(env, key)).map(([key, value]) => key + "=" + value); if (lines.length) appendFileSync(".env", "\n" + lines.join("\n") + "\n")'
```

| Команди | Локална конфигурација |
| --- | --- |
| `dev`, `start`, `worker`, `worker:check` | `.env` и `DATABASE_URL` за `aevyra_app` |
| `db:up`, `db:stop` | `.env.admin` и `POSTGRES_*` за Compose |
| `db:migrate`, `db:migrate:status` | `.env.admin` и задолжителен `DATABASE_ADMIN_URL` |
| `db:provision` | `.env.admin` за административната операција и `.env` за апликациската сметка |
| `auth:create-user` | `.env.admin` за административната конекција и `.env` за поставките на Better Auth |
| `test:*` интеграциски команди | `.env.admin` и експлицитен `TEST_DATABASE_ADMIN_URL` |

Чувајте ги двете датотеки со тајни локално. Веќе поставените променливи во околината имаат предност при вчитувањето. Користете ја апликациската адреса во нормалните веб и worker сесии. Локалното раздвојување ги ограничува оперативните PostgreSQL конекции. Пристапот до целиот локален датотечен систем дава пристап и до двете датотеки.

`REAL_SENDING_ENABLED` е оневозможено кога поставката недостасува или има точна текстуална вредност `false`. Другите вредности даваат конфигурациска грешка при проверката на серверската конфигурација.

`AUTH_BASE_URL` е фиксниот origin на вебот. Отворајте ја локалната апликација преку истата адреса, на пример `http://127.0.0.1:3000`. HTTP е дозволен со `AUTH_LOCAL_HTTP=true` и само на `127.0.0.1` или `::1`. За HTTPS користете `AUTH_LOCAL_HTTP=false` или изоставете ја поставката. `AUTH_SECRET` останува стабилна меѓу рестартирања и се чува само на серверот. Промената на тајната ги прави претходно издадените cookies невалидни.

## Стартување и проверки

Ако Docker Desktop е инсталиран во корисничката папка, а PowerShell не ја наоѓа командата `docker`, додајте ја инсталираната патека само во тековната сесија. Последната команда треба да прикаже `linux`.

```powershell
$aevyraDockerBin = Join-Path $env:LOCALAPPDATA 'Programs\DockerDesktop\resources\bin'
if (-not (Get-Command docker.exe -ErrorAction SilentlyContinue) -and
    (Test-Path -LiteralPath (Join-Path $aevyraDockerBin 'docker.exe'))) {
    $env:Path = "$aevyraDockerBin;$env:Path"
}
docker info --format '{{.OSType}}'
```

```powershell
npm.cmd run db:up
npm.cmd run db:migrate
npm.cmd run db:provision
npm.cmd run db:migrate:status
npm.cmd run auth:create-user
```

По ова, во прв PowerShell прозорец стартувајте го вебот:

```powershell
npm.cmd run dev
```

Отворете [локалната веб-страница](http://127.0.0.1:3000). Во втор PowerShell прозорец стартувајте го worker процесот или извршете ја еднократната проверка.

```powershell
npm.cmd run worker
npm.cmd run worker:check
```

По успешна почетна проверка, `worker` мирува до Ctrl+C. Тој сè уште не обработува пораки. Ако Windows побара потврда за запирање на командата `npm.cmd`, внесете `Y`. `worker:check` завршува со код `0` при успех и `1` при недостапна база или невалидна конфигурација.

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run start
npm.cmd run db:stop
```

`start` ја стартува претходно изградената веб-апликација. Запрете го развојниот веб-процес пред да користите `start` на истата порта. Изградбата може да се изврши без активна база, auth тајна и `.env.admin`. `db:stop` го запира контејнерот и го зачувува именуваниот волумен.

За повторно стартување без губење на локалните податоци користете `npm.cmd run db:up`; именуваниот `postgres_data` волумен останува. Не користете `docker compose down -v`, освен ако намерно сакате неповратно да ја избришете локалната база.

## Миграции

`db:migrate:status` ги чита датотеките во `packages/db/migrations` и историјата во `public.pgmigrations`. На празна база прикажува кои миграции чекаат без да ја создаде историјата. `db:migrate` рачно ги применува миграциите што чекаат. Излезниот код е `0` при успех и `1` при грешка или при зафатено миграциско заклучување.

За поврзување се чека до 5 секунди, а за целата миграциска операција до 5 минути. PostgreSQL има и ограничување од 5 минути по SQL наредба. Повторното извршување по успешна примена прикажува дека нема нови миграции. За промена на шемата додајте нова временски нумерирана SQL датотека. Веќе применетите датотеки се трајна историја.

## Подготовка на апликациската улога

`db:provision` ја проверува активната проектна база, администраторот и портата преку локалниот Docker Desktop Linux engine. Двете адреси мора да ја посочуваат истата база на `127.0.0.1` без URL параметри. Поставувањето на правата е трансакциско и ја користи миграциската брава. За административната операција и за проверката на новата конекција се дозволени по 30 секунди. Постојна истоимена улога мора да има проектна ознака за таа база и безбедни атрибути. Повторното извршување ја користи зачуваната лозинка.

Улогата добива `CONNECT`, `USAGE` на `aevyra` и `aevyra_auth` и `SELECT` на `aevyra.organizations`. За регистарот, `INSERT` е ограничено на `name` и `kind`, а `UPDATE` на `name`. Забранети се бришење, `TRUNCATE`, DDL, привремени објекти, доделување права, пристап до миграциската историја и преземање административна улога. Правата за auth табелите се наведени во [архитектурата](ARCHITECTURE.md). Релевантните права преку `PUBLIC` се ограничени во проектната база.

По миграциите за контакти и ограничувања, `db:provision` ги поставува и проверува `SELECT` и внесување по определени колони на деловните табели. UUID и времињата ги генерира PostgreSQL. Матрицата е во [архитектурата](ARCHITECTURE.md).

## Најава и создавање корисник

По миграциите и `db:provision`, експлицитно создајте корисник од интерактивен PowerShell терминал кога тоа е потребно. Лозинката се внесува скриено и има од 12 до 128 знаци.

```powershell
npm.cmd run auth:create-user
```

Потоа отворете [Најава](http://127.0.0.1:3000/login). `/app` и `GET /api/me` ја проверуваат сесијата на сервер. Сесијата истекува осум часа по најавата, а одјавата го укинува записот и ја чисти cookie. Профилот содржи само идентификатор, име и е-пошта. Јавната регистрација е исклучена.

Better Auth дозволува најмногу пет обиди за најава во 60 секунди по клуч и го чува бројачот во PostgreSQL. App Router во оваа конфигурација нема доверлива адреса на клиентот, па барањата делат еден клуч за патеката за најава. Клиентските `X-Forwarded-For` и други IP заглавија се игнорираат. За посебен клуч по клиент при идно поставување, доверливиот reverse proxy треба да ја утврдува адресата, да го препишува соодветното заглавие и да спречи директен пристап до веб-процесот.

## Внатрешен регистар

Во `/app`, секоја внатрешна сметка на Aevyra може да создава клиники и маркетинг бази, да ги прегледува по вид и да го менува името од страницата за детали. Сите оператори имаат ист пристап. Клиниките, пациентите и лекарите немаат сопствени сметки или клиентски пристап.

- `GET /api/organizations` прифаќа опционален `kind=CLINIC` или `kind=MARKETING`, `limit` од 1 до 100 со стандардни 25 и `cursor` од `nextCursor` во претходниот одговор. Користете го истиот филтер за следната страница. Редоследот е опаѓачки по `created_at`, па по `id`.
- `POST /api/organizations` прима JSON со `name` и `kind` и враќа 201. `GET /api/organizations/[id]` чита детали, а `PATCH` на истата адреса прифаќа само `name`. Името се скратува од околниот празен простор и има од 1 до 200 знаци.
- За сите операции е потребна валидна сесија. Запишувањето бара `Origin` еднаков на `AUTH_BASE_URL`. Одговорите на регистарот се приватни и со `no-store`.

## Преглед на датотека

Во деталите на клиника или маркетинг база отворете „Преглед на датотека“ и изберете CSV или Excel работна книга.

- За `.csv` изберете разделувач и дали првиот ред е заглавие, па кликнете „Прочитај колони“. Поддржани се запирка, точка-запирка и табулатор, UTF-8 со и без BOM, CRLF/LF и повеќелиниски полиња во наводници.
- За `.xlsx` кликнете „Прочитај листови“ и изберете лист. Опцијата за заглавие се однесува на Excel ред 1. Скриените листови се означени, а скриените и филтрираните редови се вклучуваат.
- Изберете ја телефонската колона по нејзината позиција. Серверот ја проверува целата колона и враќа до 100 примероци со изворен ред, оригинал, статус, причина и E.164 кога форматот е валиден. Дупликатите упатуваат на првиот валиден запис со истиот E.164 во тековниот избор. Шесте бројачи се за целата колона.
- XLSX бројчана ќелија е „За проверка“ поради можни изгубени нули или `+`. Формули, датуми, логички вредности, Excel грешки и неподдржани броеви во телефонската колона се одбиваат со позиција.

Серверските граници се 5 MiB за датотека, 5 MiB + 64 KiB за multipart тело, 20.000 податочни редови, 50 колони и 4.096 Unicode знаци во текстуално поле. XLSX дополнително е ограничен на 10 листови, 1.000 ZIP записи и 50 MiB декомпресирана содржина. Празните редови до последниот пополнет Excel ред се бројат како исклучени. Завршното форматирање не додава редови.

Прегледот ја проверува нумерациската валидност според `phone-normalization-v1`. Активноста на броевите, достапноста на каналите и дозволата за контакт се одделни проверки. Прегледот работи без запишување.

## Потврден увоз на контакти

Во деталите на организацијата изберете **Преглед на датотека**, поставете го разделувачот или работниот лист и изберете телефонска колона. Кога анализата ќе најде единствени валидни контакти, **Зачувај валидни контакти** го отвора резимето за проверка. **Потврди зачувување** ја испраќа оригиналната датотека за повторна анализа и зачувување. Базата ги враќа точните бројки за нови и постојни контакти. Зачувувањето не доделува дозвола за контакт.

При прекин изберете **Провери исход**. Пораката „Сè уште нема потврден резултат“ значи дека увозот може сè уште да се обработува. За повторување по освежување изберете ја истата оригинална датотека. По 30 минути за нов запис е потребно **Обнови преглед** со истата датотека и уште една потврда. Проверката на веќе завршениот исход останува достапна. **Последни увози** ги прикажува до 20 завршени увози за избраната организација.

## Зачувани контакти

Деталите на секоја клиника и маркетинг база ја прикажуваат листата на нејзините зачувани контакти. Вкупниот број е за целата организација, а бројот на совпаднати резултати е за активното пребарување. Празно пребарување ги прикажува сите контакти.

- Пребарувањето прифаќа почеток на меѓународен број со опционално `+` и од 3 до 15 цифри, со прва цифра од 1 до 9, на пример `+38970`. Се отстрануваат само околните празни места. Национални броеви, SQL wildcard знаци и друга содржина се одбиваат.
- `GET /api/organizations/[id]/contacts` прифаќа `search`, `limit` од 1 до 100 со стандардни 25 и `cursor` од претходниот одговор. Непознати и повторени параметри се одбиваат.
- Редоследот е `normalized_phone ASC, id ASC`. Потпишаниот cursor е врзан за организацијата, точниот активен префикс и последниот контакт. Секоја ставка содржи `id`, `normalizedPhone`, `createdAt` и серверски утврдено `hasSuppression`; страницата ги содржи `totalContacts`, `matchedContacts` и `nextCursor`.
- Прегледот е само за читање. Не означува дозвола, достапност на Viber, испраќање или доставување.

## Серверска евиденција „Не контактирај“

Чекор 4Б‑1 додава трајна, еднонасочна евиденција за постоен контакт во конкретна организација. Ограничувањето не се пренесува во друга клиника или маркетинг база, нема автоматско истекување и повторен увоз не го отстранува. Отсуството на запис не е дозвола за испраќање. Чекор 4Б‑1 е координаторски прифатен.

Чекор 4Б‑2 додава `GET` и `POST /api/organizations/[id]/contacts/[contactId]/suppression`. Двете операции бараат проверена серверска сесија, а `POST` бара точен доверлив `Origin`, зема оператор исклучиво од сесијата и прифаќа само `reason` и опционална `reference` во JSON тело до реални 4 KiB. Сите одговори се `private, no-store`.

- `GET` разликува постоечко ограничување, постоечки контакт без ограничување, непостоечки контакт и привремено недостапна евиденција. Недостапноста не се претставува како отсуство.
- `POST` враќа HTTP 201 за нов запис и HTTP 200 за оригиналниот постоечки запис. `ALREADY_RECORDED_DIFFERENT_METADATA` јасно кажува дека предложените нови податоци не се запишани.
- Листата користи еден организациски ограничен `LEFT JOIN`, без барање по контакт. Ознаките се „Не контактирај“ и „Нема евидентирано ограничување“; втората не значи согласност.
- При изгубен одговор интерфејсот не прогласува успех или неуспех, туку нуди „Провери исход“. Нема масовна операција, поништување, измена, дозвола за испраќање или испраќање.

```powershell
    Remove-Item Env:TEST_DATABASE_ADMIN_URL
}
```

Тестовите го проверуваат активниот проектен контејнер и експлицитната тест-адреса. Привремените бази и LOGIN улоги имаат префикс `aevyra_test_` и случаен суфикс. HTTP/UI сериите се стартуваат по успешно завршен build; не стартувајте ги додека друг процес ја менува истата `.next` папка. Тестовите користат синтетички контакти и сметки под `example.test`. По затворање на конекциите се отстрануваат само ресурсите создадени во тековното извршување. `npm.cmd test` ги извршува основните тестови, вклучувајќи ги читачите за CSV и XLSX. Никогаш не користете вистински контактни бази во тест.

## Достапност

- `GET /api/health/live` враќа HTTP 200 кога веб-процесот одговара.
- `GET /api/health/ready` проверува PostgreSQL со `SELECT 1`. Враќа HTTP 200 за достапна база и HTTP 503 за недостапна база или невалидна серверска конфигурација. Овој одговор ја опишува достапноста на базата.

Ако Docker или Compose недостигаат, можете да ја стартувате веб-апликацијата и да ги извршите статичките проверки, тестовите и изградбата. Додека нема достапен PostgreSQL, страницата прикажува недостапност, а еднократната проверка завршува со код `1`.

Ако Docker е достапен, проверете дали работи со `docker info` и дали базата е здрава со `docker compose --env-file .env.admin ps`. При промена на локалната порта, усогласете ги `POSTGRES_PORT` и двете PostgreSQL адреси. Стартувајте ги веб-процесот и работниот процес повторно по промена на `.env`.

`db:provision` е намерно ограничен на локалниот Docker Desktop Linux engine, `127.0.0.1` и проверениот Compose проект. Ова не е VPS provision алатка и проектот нема потврдена продукциска постапка за распоредување.

Видете [запис за проверките](TESTING.md) и [тековна состојба](PROGRESS.md).
