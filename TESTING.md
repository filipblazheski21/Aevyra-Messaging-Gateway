- Chrome добива посебна папка од `mkdtemp` под каноничниот системски привремен корен. Пред рекурзивно бришење се проверуваат апсолутниот родител, префиксот, видот на објектот, отсуството на reparse/symbolic link и каноничната патека.
- Првото затворање е DevTools `Browser.close` со рок. Ако останат процеси, WMI/CIM ги избира само `chrome.exe` процесите чија командна линија ја содржи точната апсолутна патека на профилот од тековното извршување. Само тие PID вредности смеат резервно да се запрат; потоа повторно се чека со конечен рок, па дури тогаш се брише профилот.
- Намерната грешка во сценарио беше вратена како истиот `Error`, а профилот и процесите беа 0. При синтетичка дополнителна грешка во чистењето беше вратен `AggregateError` со првичната причина прва и причината за чистење втора. И неуспехот по создавање профил, но пред стартување Chrome, го исчисти профилот.
- Само `pg.DatabaseError` од тест-сценарио добива безбедна PostgreSQL порака. Синтетичка `EPERM` датотечна грешка остана непроменета. Познатите операции за поставување и чистење на тест-базата се обвиткани според нивниот контекст, без URL, лозинка, SQL параметри или чувствителни детали во корисничката порака.
- Забележаната независна грешка од претходното извршување не може ретроактивно да се идентификува по точен Windows код: старото прекласифицирање го изгубило оригиналот. Кодот докажува дека секоја не-assertion грешка со `code`, вклучително датотечна, била погрешно означувана како PostgreSQL; тоа ја објаснува можноста, но не докажува која била историската причина.

Првиот развоен обид на новите helper тестови создаде четири профилни папки пред да ја открие грешката во PowerShell повикот. Read-only проверката потврди 0 процеси за нив, по што беа отстранети само четирите точно именувани папки, со проверени привремен корен, обична папка, отсуство на reparse point и 0 сопствени процеси. Сите наредни успешни и намерно неуспешни текови се исчистија самостојно.

Завршната развојна база има 0 организации, 0 контакти, 0 увози, 0 врски, 0 ограничувања и 0 записи во петте auth табели. Има 4 применети миграции и 0 за примена. `REAL_SENDING_ENABLED=false`; не се извршени миграција, provision, ресетирање база или ресетирање Docker волумен. Апликацискиот интерфејс не е изменет; постојните широки и тесни UI сценарија останаа зелени.
